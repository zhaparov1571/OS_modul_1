# Проект 2 — Взаимоблокировки в банке

**Модуль 1, часть Б. Базовый уровень A.** Язык: Python 3 (все библиотеки стандартные). Работает на Ubuntu/WSL2, Windows и Linux.

## Цель

Обнаружить взаимоблокировку (`deadlock`) при переводах между двумя банковскими счетами, устранить её **без `sleep` и `timeout`**, определить безопасное и небезопасное состояния с помощью **алгоритма банкира**.

## Задание A1 — диагностика взаимоблокировки

В исходном `transfer_deadlock.py` оба потока находятся на **строке 23**, где пытаются взять вторую блокировку (`with locks[dst]:`). Первый кассир уже держит A и ждёт B; второй держит B и ждёт A. Главный поток стоит на **строке 31** (`join()`) и ждёт их. `faulthandler` через 5 секунд выводит стеки потоков; это **диагностика**, а не исправление.

## Задание A2 — исправление

`transfer_fixed.py` при любом направлении перевода захватывает блокировки **в одинаковом порядке**: сначала A, потом B. Код использует `sorted((src, dst))`. Это исключает *циклическое ожидание*, одно из четырёх условий Коффмана. `sleep()` или `timeout` в исправлении не используются. Итог после 100 переводов каждым кассиром:

```text
Готово: {'A': 1000, 'B': 1000} сумма = 2000
Проверка: 200 переводов выполнены, deadlock отсутствует, общая сумма сохранена.
```

## Задание A3 — алгоритм банкира

Считаем потребности процесса: **Need = Max − Allocation**. Начальные свободные ресурсы: **Work = Available**. Пока возможно, выбираем незавершённый процесс с `Need <= Work`, считаем его завершённым, возвращаем его `Allocation` в `Work`. Если удаётся завершить все процессы — `SAFE`, иначе `UNSAFE`.

- `bank_state.txt`: **SAFE**. Одна безопасная последовательность: `P4 → P3 → P1 → P2 → P0`.
- `bank_state2.txt`: **UNSAFE**. Возможно завершить только `P4`; у оставшихся потребности больше доступных ресурсов, безопасной полной последовательности нет.

**Важно:** `UNSAFE` — отсутствие гарантированной безопасной последовательности, это не обязательно уже случившийся deadlock.

Дополнительно в `banker.py` выполнена проверка `requests.txt` (это задание уровня B, не требуется для сдачи базового A). Каждый запрос проверяется **независимо от первоначального состояния**, как написано в файле.

## Краткий вывод

Deadlock возникает из-за противоположного порядка захвата двух блокировок. Единый порядок захвата полностью убирает циклическое ожидание. Алгоритм банкира позволяет заранее оценить, сможет ли система безопасно удовлетворить процессы при текущем распределении ресурсов.
